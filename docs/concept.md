# 인지 부채(Cognitive Debt) 10분 체험 웹앱 구상안

> 한 줄 요약: **"숙제는 AI와, 시험은 혼자"** 를 10분 안에 압축해서 겪게 한다.
> 같은 사람이 "혼자 풀기"와 "AI와 풀기"를 모두 해 본 뒤, AI 없는 시험에서
> 두 결과를 나란히 비교하고, 마지막에 **"인지 부채 청구서"** 를 받는다.

---

## 1. 무엇을 체험하게 할 것인가

### 인지 부채란
AI에게 생각을 맡기면 **지금은 편하지만(대출)**, 나중에 기억·이해·응용 능력으로
**이자를 치르게 된다(상환)** 는 개념. MIT Media Lab의 2025년 연구
("Your Brain on ChatGPT", Kosmyna 외)에서 쓰인 용어로, ChatGPT로 에세이를
쓴 집단은 뇌 연결성이 가장 낮았고, 방금 쓴 글에서 한 문장도 인용하지 못한 비율이
83%에 달했으며, 글에 대한 주인의식도 낮았다.

### 체험이 노려야 할 "아하" 3가지
| 아하 | 학생의 체감 | 뒷받침 근거 |
|---|---|---|
| **기억 부채** | "AI가 답을 알려줬는데, 그 답이 뭐였는지 기억이 안 나네?" | 생성 효과(Slamecka & Graf 1978), 구글 효과(Sparrow 외 2011) |
| **학습 부채** | "풀이까지 봤는데, 비슷한 문제를 못 풀겠네?" | 바람직한 어려움(Bjork), MIT 2025 |
| **자신감 착시** | "자신 있었는데 틀렸네?" | Microsoft/CMU 2025 (AI 신뢰도↑ → 비판적 사고↓) |

세 가지를 **한 사람 안에서, 10분 안에, 숫자로** 보여주는 것이 목표다.
설명이 아니라 결과표가 설득한다.

## 2. 설계 원칙 6가지

1. **개념은 맨 마지막에 공개한다.** 처음엔 "10분 학습 실험"이라고만 안내한다.
   "인지 부채"를 먼저 말하면 학생이 의식적으로 더 노력해서 효과가 사라진다.
2. **자기 자신이 대조군이다.** 한 사람이 두 조건을 모두 겪는다(within-subject).
   반 전체 통계가 없어도 혼자서 "아하"가 가능해야 한다.
3. **빌릴 때는 달콤하게, 갚을 때는 분명하게.** AI 조건이 끝나면
   "⚡ 1분 12초 절약!"처럼 기분 좋게 보여준다. 그래야 시험에서 받는 청구서가 아프다.
4. **측정은 가볍게.** 10분 동안 자기보고 탭은 4번 이내. 나머지는 자동 기록(시간, 정답, 클릭).
5. **반(反)AI 메시지가 아니다.** 끝은 금지가 아니라 처방으로 맺는다.
   ("먼저 생각하고, 그다음 AI" : MIT 연구에서도 Brain→LLM 순서 집단은 성과가 좋았다.)
6. **스마트폰에서 로그인 없이 30초 안에 시작.** 교실 현장은 로그인에서 무너진다.

## 3. 10분 타임라인

| 구간 | 시간 | 화면 | 하는 일 |
|---|---|---|---|
| 0. 입장 | 0:30 | 시작 | 역할(학생/교사) 선택, 닉네임, "짧은 학습 실험" 안내. 조건 순서 무작위 배정 |
| 1. 숙제 ① | 2:00 | 숙제 | 유형 X를 **조건 P**로 풀기 (예: 숫자 기계를 혼자) |
| 2. 숙제 ② | 2:00 | 숙제 | 유형 Y를 **조건 Q**로 풀기 (예: 글자 규칙을 AI 튜터와) |
| 3. 쉬는 시간 | 1:00 | 설문 | "평소 숙제할 때 AI를 얼마나 쓰나요?" 4문항. **실제 목적은 기억 간섭(방해 과제)** |
| 4. 시험 | 2:30 | 시험 | 유형별 자신감 예측 1탭 → 기억 1문제 + 응용 1문제. **AI 없음, 타이머 있음** |
| 5. 청구서 | 1:30 | 결과 | 혼자 vs AI 결과 나란히, 개념 공개, 처방 3가지, 공유 카드 |
| (교사) 토론 | +5:00 | 대시보드 | 반 집계 보고 토론. 10분 밖의 선택 구간 |

- 조건 순서(혼자→AI / AI→혼자)와 유형 배정(X/Y)은 접속 시 무작위. 반 집계 시 순서 효과가 상쇄된다.
- 타이머가 끝나면 자동으로 다음 화면. 10분을 지키는 건 사용자가 아니라 앱이다.

## 4. 과제 설계: "규칙 찾기" 두 유형

글쓰기 대신 **규칙 찾기 퍼즐**을 1차 모듈로 제안하는 이유:
- 초등 고학년부터 교사까지 같은 문제를 쓸 수 있다(글쓰기 실력 무관).
- 정답이 짧아 자동 채점된다.
- "풀이를 봤다"와 "직접 풀었다"의 차이가 **응용 문제**에서 바로 드러난다.
- 숙제 → 시험이라는 학교 맥락과 1:1로 대응된다.

### 유형 X: 숫자 기계 (수 규칙)
```
예시:  2 → 7     4 → 13     5 → 16        (규칙: ×3 + 1)
숙제:  7 → ?  (22)      3 → ?  (10)
시험(기억):  "숙제에서 7 → ? 의 답은?"            → 22
시험(응용):  11 → ?                                → 34
```

### 유형 Y: 글자 규칙 (낱말 규칙)
```
예시:  별 → 벌    달 → 덜    산 → 선        (규칙: 모음 ㅏ → ㅓ)
숙제:  밤 → ?  (범)      강 → ?  (겅)
시험(기억):  "숙제에서 밤 → ? 의 답은?"            → 범
시험(응용):  말 → ?                                → 멀
```

두 유형은 구조(예시 3개 → 규칙 추론 → 적용)는 같고 모달리티(수/글자)가 달라서,
한쪽에서 배운 요령이 다른 쪽 시험으로 새어 나가는 오염을 줄인다.
난이도는 파일럿에서 혼자 풀기 정답률이 두 유형 모두 60~80%가 되도록 맞춘다.
문제 은행은 유형당 3세트 이상 두고 무작위로 뽑는다(같은 반에서 베끼기 방지).

### 두 조건의 화면 차이

**혼자 풀기 (Brain-only)**
- 예시 3쌍 + 답 입력칸 2개 + 타이머.
- 힌트 없음. 60초 후 "모르겠어요" 버튼만 등장(좌절 방지).
- 제출 후 정답과 규칙 한 줄을 보여준다(피드백).
  → AI 조건과 "정보량"은 같아지고, **먼저 씨름했는가**만 다르게 만든다.

**AI 튜터와 풀기 (AI-assisted)**
- 같은 화면 + 오른쪽(모바일은 아래)에 "AI 튜터" 채팅 패널.
- 빠른 버튼 2개: **[힌트만 줘]** / **[답 알려줘]**. 자유 입력도 가능.
- AI는 1~2초 타이핑 애니메이션 뒤 답과 풀이를 보여준다(스크립트 응답, 실제 LLM 불필요).
- 학생은 그래도 답을 **직접 입력해 제출**해야 한다(현실의 "베껴 적기"와 동일).
- 어떤 버튼을 눌렀는지 기록한다. 교사 토론의 핵심 데이터가 된다
  ("우리 반 87%가 힌트 대신 바로 답을 요청했다").
- 제출 직후 보상 메시지: "⚡ 38초 만에 완료! 혼자 풀 때보다 1분 21초 빨랐어요."

## 5. 시험과 측정

시험 직전, 유형별로 1탭 예측: **"이 유형, 시험에 나오면 풀 수 있을 것 같아요?"** 😟 😐 😎
→ 자신감(JOL, 학습 판단)을 기록한다. 자신감과 실제 점수의 차이가 "착시" 지표.

유형당 2문제, 문제당 30초 제한, 피드백 없음(청구서에서 한꺼번에).

| 지표 | 혼자 | AI | 자동 기록 여부 |
|---|---|---|---|
| 숙제 소요 시간 | 1:59 | 0:38 | 자동 |
| 숙제 정답 | ○ | ○ | 자동 |
| 요청한 도움 종류 | - | 답 알려줘 | 자동 |
| 시험 자신감 | 😐 | 😎 | 1탭 |
| 시험 기억 문제 | ○ | ✕ | 자동 |

## 6. 결과 화면: "인지 부채 청구서"

청구서(영수증) 형태로 보여준다. 은유가 곧 교육 내용이다.

```
┌──────────────────────────────────┐
│   🧾 인지 부채 청구서            │
│   고객: 민지                     │
├──────────────────────────────────┤
│   빌린 것                        │
│   · 숙제 시간 절약     1분 21초  │
│   · 머리 쓰는 수고     거의 0    │
├──────────────────────────────────┤
│   이자                           │
│   · 시험 기억 문제     ✕ (혼자: ○)│
│   · 시험 응용 문제     ✕ (혼자: ○)│
│   · 자신감 - 실력 차이  +2        │
├──────────────────────────────────┤
│   합계: 1분 21초 아끼고,         │
│         시험 2문제를 잃었습니다. │
└──────────────────────────────────┘
```

이어서 3단 구성:
1. **개념 공개 (3줄)**: 인지 부채가 무엇인지, MIT 2025 연구 한 줄, "당신 결과도 같은 패턴".
2. **처방 3가지**
   - 먼저 내 답을 쓴 뒤 AI에게 묻기 (Brain → AI 순서)
   - AI 답을 받으면 **내 말로** 다시 설명하기
   - AI 없이 한 번 더 풀어 보기 (셀프 테스트)
3. **공유 카드**: 청구서 이미지 저장. 교사라면 "반 결과 보기" 버튼.

**부채가 없는 사람**의 결과도 설계한다. "힌트만 요청"했거나 두 유형 모두 시험을 맞힌
사람에게는 "🎉 부채 0원. 비결: 힌트만 받고 직접 풀었음"처럼 **좋은 AI 사용법을
보상**한다. 이게 없으면 "AI 쓰면 무조건 나쁘다"로 읽힌다.

## 7. 교사 모드

- **수업 코드 생성** → 학생은 코드만 입력해 입장(로그인 없음).
- **실시간 대시보드**: 참여 인원, 혼자 vs AI 평균(숙제 시간, 시험 정답률, 기억률, 자신감 차이),
  "답 알려줘" 선택 비율, 조건 순서별 분리 보기.
- **5분 토론 가이드**(화면 하단 고정)
  1. AI가 풀이까지 보여줬는데 왜 기억이 안 났을까?
  2. "답 알려줘"와 "힌트만 줘"를 고른 친구들의 시험 결과는 어떻게 달랐을까?
  3. 숙제에서 AI를 써도 시험을 잘 보려면 어떻게 써야 할까?
- **CSV 내보내기**(닉네임, 조건 순서, 지표 전체).
- 교사도 먼저 학생 모드로 10분을 직접 체험하도록 유도한다(연수용).

## 9. 기술 구상

**MVP = 솔로 모드, 프런트엔드만.**
- Vite + React + TypeScript, Tailwind. 모바일 우선, 정적 배포(Vercel).
- 상태와 결과는 localStorage. 서버 없음.
- 문제 은행은 JSON. AI 튜터 응답은 **스크립트(사전 작성)**. 실제 LLM을 쓰지 않는 이유:
  지연 없음, 비용 0, 반 전체가 같은 난이도, 네트워크 없어도 동작.
  (추후 "자유 질문" 기능에만 실제 모델을 붙이는 옵션을 둘 수 있다.)
- 타이핑 애니메이션과 1~2초 지연으로 "AI 느낌"을 준다.

**2단계 = 교사 모드.**
- Supabase 테이블 2개: `sessions(code, created_at)`, `results(session_code, nickname, order, metrics_json)`.
- 대시보드는 realtime 구독으로 갱신.

**기록 스키마(1인 1행)**
```
nickname, role, order(brain_first|ai_first), type_brain(X|Y),
hw_brain_time, hw_brain_correct, hw_ai_time, hw_ai_correct, ai_help_type(hint|answer|none),
conf_brain, conf_ai,
exam_brain_recall, exam_brain_transfer, exam_brain_time,
exam_ai_recall, exam_ai_transfer, exam_ai_time,
survey_ai_usage(1-5), created_at
```

## 10. 주의할 점

- **이건 시연이지 실험이 아니다.** n=1에서는 효과가 안 나올 수 있다.
  청구서 하단에 "결과는 사람마다 다릅니다. 핵심은 '내가 어떻게 AI를 썼는가'를 돌아보는 것"을 넣는다.
- **MIT 연구는 인용을 정확히.** 참가자 54명, EEG, 에세이 과제, 2025년 프리프린트.
  "AI를 쓰면 멍청해진다"로 과장하지 않는다.
- **순서 효과**: 솔로 모드에서도 무작위. 반 집계에서는 순서별로 나눠 볼 수 있게 한다.
- **좌절 관리**: 혼자 풀기가 너무 어려우면 체험이 "나는 원래 못해"로 끝난다. 정답률 60~80%가 목표.
- **개인정보**: 닉네임만. 교사 대시보드는 코드 기반, 세션은 24시간 후 삭제.

## 11. 확장 모듈 (나중에)

- **글쓰기 모듈**: MIT 연구와 같은 방식. 3문장 주장 쓰기(혼자 vs AI 초안 고르기) → 1분 뒤
  "내 글의 첫 문장을 기억나는 대로 쓰기" + 주인의식 평가. 고등학생·교사 연수용.
- **영어 단어 모듈**: 문맥에서 뜻 추론하기 vs AI 번역 → 새 문장 번역 시험.
- **문제 유형 추가**: 도형 규칙, 수열, 간단 암호.
- **반복 체험**: 일주일 뒤 재시험 링크(장기 기억 부채 보여주기).

## 12. 만들기 순서 제안

1. 문제 은행 JSON + 솔로 모드 6화면 (S0~S5). 여기까지가 "10분 체험" 완성.
2. 교사와 학생 5명 파일럿. 난이도와 타이머를 조정한다.
3. 교사 대시보드(T1) + Supabase.
4. 공유 카드 이미지, 확장 모듈.
