# 인지 부채(Cognitive Debt) 10분 체험 웹앱 구상안 (v2)

> 한 줄 요약: **내가 직접 쓴 글과 AI가 써 준 글, 몇 분 뒤 어느 쪽이 더 기억나는가?**
> 같은 사람이 두 가지 짧은 글을 쓴다. 하나는 직접, 하나는 AI 도우미와.
> 몇 분 뒤 두 글에 대한 기억 시험을 치르고, 결과를 나란히 비교한 **"인지 부채 청구서"** 를 받는다.

---

## 1. 무엇을 체험하게 할 것인가

### 인지 부채란
AI에게 생각을 맡기면 **지금은 편하지만(대출)**, 나중에 기억·이해·주인의식으로
**이자를 치르게 된다(상환)** 는 개념. MIT Media Lab의 2025년 연구
("Your Brain on ChatGPT", Kosmyna 외, 참가자 54명, EEG)에서 쓰인 용어다.
ChatGPT로 에세이를 쓴 집단은 **방금 쓴 자기 글에서 한 문장도 정확히 인용하지 못한 비율이 83%** 였고
(직접 쓴 집단은 약 10%), 글에 대한 주인의식도 가장 낮았다.

### 이 앱이 재현하는 것
MIT 실험의 핵심 장면 하나를 10분으로 압축한다.
**"네가 제출한 글의 첫 문장을 말해 봐."**

| 학생이 겪는 "아하" | 측정 | 뒷받침 근거 |
|---|---|---|
| **기억 부채**: "AI 글은 방금 읽었는데 한 문장도 안 떠오르네?" | 첫 문장 인용 일치율, 빈칸 채우기 | 생성 효과(Slamecka & Graf 1978), MIT 2025 |
| **주인의식 부채**: "이게 내 글이라는 느낌이 안 드네?" | '내 글' 느낌 0~100 | MIT 2025 (ownership 저하) |
| **자신감 착시**: "기억날 줄 알았는데?" | 시험 전 예측 vs 실제 점수 | Microsoft/CMU 2025, 메타인지 연구 |

## 2. 설계 원칙 6가지

1. **개념은 맨 마지막에 공개한다.** 처음엔 "짧은 글쓰기 실험"이라고만 안내한다.
   "기억 시험이 있다"는 것도 말하지 않는다. 알면 외우려 들어서 효과가 사라진다.
2. **자기 자신이 대조군이다.** 한 사람이 직접 쓰기와 AI 쓰기를 모두 겪는다.
   반 통계가 없어도 혼자서 "아하"가 가능해야 한다.
3. **AI 조건은 현실처럼.** 학생이 직접 AI에게 요청 문장을 치고, 초안을 받고, 고칠 수 있고, 제출한다.
   "클릭 한 번으로 끝"이 아니라 실제 학생이 AI를 쓰는 방식 그대로여야 결과가 설득력을 가진다.
4. **빌릴 때는 달콤하게, 갚을 때는 분명하게.** AI 조건이 끝나면 "⚡ 1분 17초 절약, 타자 0자"처럼
   기분 좋게 보여준다. 그래야 청구서가 아프다.
5. **반(反)AI 메시지가 아니다.** 끝은 금지가 아니라 "AI와 쓰더라도 내 글로 남기는 법"으로 맺는다.
   MIT 연구에서도 **먼저 직접 쓰고 나중에 AI를 쓴 집단**은 기억과 뇌 활성이 좋았다.
6. **스마트폰에서 로그인 없이 30초 안에 시작.** 글쓰기도 폰 타자 기준으로 분량을 잡는다.

## 3. 10분 타임라인

| 구간 | 시간 | 화면 | 하는 일 |
|---|---|---|---|
| 0. 입장 | 0:30 | 시작 | 역할(학생/교사), 닉네임, "짧은 글쓰기 실험" 안내. 주제·조건 순서 무작위 배정 |
| 1. 글쓰기 ① | 2:00 | 글쓰기 | 주제 A를 **조건 P**로 (예: 직접 쓰기) |
| 2. 글쓰기 ② | 2:00 | 글쓰기 | 주제 B를 **조건 Q**로 (예: AI 도우미와 쓰기) |
| 3. 쉬는 시간 | 1:00 | 설문 | "평소 글쓰기 숙제에 AI를 얼마나 쓰나요?" 4문항. **실제 목적은 기억 간섭(방해 과제)** |
| 4. 기억 시험 | 3:00 | 시험 | 글마다: 예측 1탭 → 첫 문장 인용 → 빈칸 3개 → '내 글' 느낌. **글 다시 보기 불가** |
| 5. 청구서 | 1:30 | 결과 | 두 글 나란히 비교, 개념 공개, 처방 3가지, 공유 카드 |
| (수업) 함께 나눠보기 | +7:00 | 발표 화면 | 교수자가 큰 화면에서 반 결과 공개 → 겹쳐보기 갤러리 → "누가 썼을까?" 퀴즈 → 한 줄 소감·토론. 7절 참고 |

- 조건 순서(직접→AI / AI→직접)와 주제 배정(A/B)은 접속 시 무작위. 반 집계에서 순서 효과가 상쇄된다.
- 타이머가 끝나면 자동으로 다음 화면. 10분을 지키는 건 사용자가 아니라 앱이다.
- 수업에서는 **10분 개인 체험 + 7분 함께 나눠보기 = 약 17분**이 한 세트다. 개인 체험만 하면 10분.

## 4. 글쓰기 과제

### 형식
**"주장 1문장 + 이유 2문장", 총 3문장(60~120자).** 폰 타자로 2분 안에 가능한 분량이다.
두 주제는 사전지식이 필요 없는 찬반 주제로, 친숙도가 비슷한 쌍을 고른다.

예시 주제 쌍 (앱에는 3쌍 이상 준비, 무작위 선택):
- A: "학교에 휴대폰을 가져오는 것을 허용해야 할까?"
- B: "학교 급식 메뉴를 학생이 정해야 할까?"
- (다른 쌍) "교복을 없애야 할까?" / "쉬는 시간을 20분으로 늘려야 할까?"

### 조건 1: 직접 쓰기
- 주제 카드 + 글 입력창 + 글자 수·문장 수 + 타이머 2:00.
- AI 없음. 접힌 "문장 시작 도움말"만 제공 (예: "나는 ~에 찬성한다. 왜냐하면 ~").
- 2문장·40자 이상이면 제출 가능. 시간이 끝나면 쓴 만큼 자동 제출(20자 미만이면 30초 1회 연장).
- 기록: 소요 시간, 글자 수, 타자 수.

### 조건 2: AI 도우미와 쓰기
- 같은 주제 카드 + 글 입력창 + 아래에 **"AI 글쓰기 도우미"** 채팅.
- 학생이 요청을 직접 입력한다. 입력창 예시: "휴대폰 허용에 찬성하는 글 3문장 써줘".
  빠른 칩 2개: **[찬성으로 써줘]** **[반대로 써줘]**.
- AI는 2~3초 타이핑 애니메이션 뒤 3문장 초안을 **입력창에 바로 넣어 준다**. 학생은 고칠 수 있다.
- 버튼: **[다시 써줘]** (다른 초안으로 교체) / **[제출]**.
- 기록: 요청 문장, 칩 사용 여부, 다시 쓰기 횟수, **수정 비율**(초안 대비 바뀐 글자 %),
  **읽기 시간**(초안 등장 → 제출), 소요 시간.
- 제출 직후 보상 메시지: **"⚡ 41초 완료! 타자 0자."**
  (직접 쓰기를 먼저 했다면 "직접 쓸 때보다 1분 17초 빨랐어요"까지.)

### AI는 진짜 LLM이 아니어도 된다
주제별로 **찬성 초안 3개 + 반대 초안 3개**를 미리 써 둔다.
요청 문장에 "반대"가 있으면 반대 초안, 없으면 찬성 초안을 순서대로 낸다("다시 써줘"마다 다음 것).
장점: 지연 없음, 비용 0, 반 전체가 같은 품질의 글을 받음, 네트워크 없이 동작.
(추후 옵션으로 실제 모델 연결. 교실에서는 스크립트 모드가 기본.)

## 5. 기억 시험 (글마다 약 85초, 두 글 순서 무작위)

시험 화면에서 글은 **"휴대폰 글", "급식 글"처럼 주제로만** 부른다.
"직접 쓴 글"/"AI 글"이라고 부르면 그 자체가 힌트가 된다.

| # | 문항 | 시간 | 채점 |
|---|---|---|---|
| a | **예측** "이 글, 얼마나 기억날 것 같아요?" 😟 😐 😎 | 1탭 | 자신감 1~3 |
| b | **첫 문장 인용** "제출한 글의 첫 문장을 기억나는 대로 써 보세요." | 40초 | 원문과 글자 단위 유사도 0~100% |
| c | **빈칸 채우기** 2·3번째 문장을 보여주되 어절 3개를 빈칸으로 | 40초 | 어절별 유사도 70% 이상이면 정답, 0~3점 |
| d | **'내 글' 느낌** "이 글은 얼마나 '내 글'인가요?" | 슬라이더 0~100 | 주인의식 |

- (b)는 MIT의 "인용 과제"를 그대로 옮긴 것. 두 조건 모두 제출한 원문이 있으므로 자동 채점이 가능하다.
- (c)의 빈칸은 첫 문장을 제외한 어절 중 2글자 이상, 서로 붙어 있지 않은 **긴 어절 3개**를 고른다
  (내용어일 확률이 높다). 글이 2문장이면 2번째 문장에서 고른다.
- 유사도는 띄어쓰기·문장부호를 뺀 글자 2-gram 겹침(Dice)으로 계산한다. 한국어에서 단순하고 안정적이다.
- 시험 중 글 다시 보기, 뒤로 가기 불가.

(선택, 2단계) **요지 회상**: "글에서 든 이유 하나를 말해 보세요" → 원문과 나란히 보여 주고 학생이 ○/△/✕ 자가 채점.

## 6. 결과 화면: "인지 부채 청구서"

### 6-1. 나란히 비교
```
                      직접 쓴 글        AI와 쓴 글
 쓰기 시간              1:58              0:41
 타자 수                112자             0자
 시험 전 예측            😐                😎
 첫 문장 인용 일치율     78%               23%
 빈칸 채우기             3/3               0/3
 '내 글' 느낌            85                40
```
아래에 두 글의 **원문과 내가 기억해 쓴 문장을 겹쳐서** 보여 준다(일치한 부분은 초록, 틀린 부분은 회색).
AI 글은 **초안에서 내가 고친 부분**도 표시한다. 보통 거의 없다. 이 두 장면이 가장 강한 시각 자료다.

### 6-2. 청구서
```
┌──────────────────────────────────┐
│   🧾 인지 부채 청구서            │
│   고객: 민지                     │
├──────────────────────────────────┤
│   빌린 것                        │
│   · 글쓰기 시간 절약     1분 17초 │
│   · 타자                 112자   │
├──────────────────────────────────┤
│   이자                           │
│   · 첫 문장 기억        -55%p    │
│   · 빈칸 채우기         -3개     │
│   · '내 글' 느낌        -45      │
│   · 예측과 실제 차이     😎 → 23% │
├──────────────────────────────────┤
│   합계: 1분 17초 아끼고,         │
│   글 한 편을 기억에서 잃었습니다. │
└──────────────────────────────────┘
```

### 6-3. 개념 공개와 처방
1. **개념 (3줄)**: 인지 부채가 무엇인지. "MIT 실험에서 AI로 글을 쓴 사람 83%가 자기 글을 인용하지 못했습니다.
   지금 당신 결과도 같은 패턴입니다."
2. **처방 3가지: AI와 쓰더라도 내 글로 남기는 법**
   - 먼저 내 생각을 3줄 쓰고, 그다음 AI에게 다듬어 달라고 하기 (직접 → AI 순서)
   - AI 초안을 받으면 **최소 한 문장은 내 말로 다시 쓰기**
   - 제출 전에 글을 가리고 **첫 문장을 말해 보기** (셀프 인용 테스트)
3. **공유 카드**: 청구서 이미지 저장. 교사라면 "반 결과 보기".

### 6-4. 부채가 없는 사람
AI 글의 기억 점수가 직접 쓴 글과 비슷하거나 높으면 **"🎉 부채 0원"** 과 함께 비결을 보여 준다.
"초안을 38% 고쳤고 24초 동안 읽었어요. 이렇게 쓰면 AI 글도 내 글이 됩니다."
이 화면이 없으면 체험이 "AI 쓰면 무조건 나쁘다"로 읽힌다.

## 7. 교수자 모드: 운영 · 수합 · 나눔

교수자 모드는 세 가지 일을 한다. **운영**(참여자를 모아 진행을 제어), **수합**(모든 글과 결과를 한곳에),
**나눔**(결과를 반 전체가 함께 보고 이야기하기). 세 축이 다 있어야 "수업"이 된다.

### 7-1. 운영 (진행 관리)

**세션 만들기**
- 교수자가 "수업 만들기" → 6자리 **수업 코드 + QR** 생성. 교수자는 **진행 PIN**(4자리)만 기억하면 된다.
  계정 가입 없음. (추후 계정 연동 옵션)
- 설정: 주제 쌍 선택, 글쓰기 타이머(기본 2:00), AI 모드(스크립트/실제 모델), 보관 기간(기본 30일),
  글 원문 공유 범위(교수자만 / 수업 중 익명 공개 허용).

**대기실 (로비)**
- 학생은 코드 입력 → 닉네임 → 대기실. 교수자 화면에 **참여자 타일**이 실시간으로 늘어난다.
- 중복 닉네임 자동 처리(민지, 민지2). 교수자는 타일을 눌러 퇴장시킬 수 있다.
- 동의 안내 1줄: "내 글과 결과는 익명으로 수업 시간에 함께 볼 수 있어요." 체크 해제 시
  집계에는 포함되지만 갤러리·퀴즈에는 나오지 않는다.

**두 가지 진행 방식**
| | 동기 진행 (교실, 권장) | 자율 진행 (과제·원격) |
|---|---|---|
| 시작 | 교수자가 **[모두 시작]** 을 누르면 전원 동시에 글쓰기 ① 시작 | 링크만 배포, 학생이 아무 때나 10분 |
| 단계 전환 | 개인 타이머로 자동 진행. 교수자는 필요 시 **[전체 다음 단계]** 로 강제 이동 | 자동 |
| 개인 청구서 | 끝낸 학생은 즉시 자기 결과를 본다 (개인적 "아하"는 바로) | 즉시 |
| 반 결과 | 교수자가 **[반 결과 공개]** 를 눌러야 열린다 (모두 끝난 뒤 함께) | 교수자가 공개 시점 설정 |
| 지각자 | 글쓰기 ① 시작 후에는 **관전 모드**(큰 화면 내용만 보기) | 제한 없음 |

**진행 현황판 (교수자 화면 상단 고정)**
- 단계별 인원: `대기 3 · 글쓰기 12 · 시험 9 · 완료 4`
- 참여자 타일마다 현재 단계와 진행률 링. 멈춰 있는 학생(60초 이상 입력 없음)은 노란 테두리.
- 버튼: **[모두 시작] [일시 정지] [전체 다음 단계] [반 결과 공개] [퀴즈 시작] [세션 종료]**

### 7-2. 수합 (데이터 모아보기)

**1인 1행으로 전부 저장된다.** 두 글 원문, AI 초안과 요청 문장, 수정 비율, 읽기 시간,
시험에서 학생이 기억해 쓴 문장, 빈칸 답, 점수, 예측, '내 글' 느낌, 설문, 소감.

**수합 화면 (T2)**
- 표 보기: 학생 × 지표. 열 정렬·필터(조건 순서, 주제, 수정 비율 구간).
- 학생 상세 서랍: 그 학생의 **원문과 기억 문장 겹쳐보기**, AI 초안과 최종 글 diff, 타임라인(언제 무엇을 눌렀나).
- **내보내기**: CSV / XLSX (원문 포함 또는 제외 선택), 수업 리포트 PDF.
- 보관: 기본 30일, 교수자가 연장 또는 즉시 삭제. 글 원문은 교수자와 본인만 본다.
- 여러 반을 운영하면 **세션 목록**에서 반별로 열고, 반 간 집계 비교(2단계).

### 7-3. 나눔 (함께 나눠보기, 약 7분)

교수자 화면에 **[발표 모드]** 가 있다. 프로젝터용 큰 화면이고, 학생 폰은 투표·소감 입력용 리모컨이 된다.
교수자가 슬라이드처럼 한 장씩 넘긴다.

| 순서 | 시간 | 큰 화면 | 학생 폰 |
|---|---|---|---|
| ① 반 결과 공개 | 1:00 | 직접 vs AI 평균 비교표가 **애니메이션으로** 채워진다. 첫 문장 일치율 두 분포(히스토그램)가 나란히 | 자기 점수 위에 **"반에서 내 위치"** 점이 찍힌 같은 그래프 |
| ② 겹쳐보기 갤러리 | 1:30 | 동의한 학생의 글 2~3편을 **익명으로** 띄운다: 원문 위에 기억 문장 겹쳐보기 (직접 쓴 글 1, AI 글 1~2). 교수자가 고르거나 "무작위" | 같은 화면 미러링 |
| ③ "누가 썼을까?" 퀴즈 | 2:30 | 글 4편을 보여 준다(직접 2, AI 2, 익명). "AI가 쓴 글은 어느 것?" → 투표 결과 막대가 실시간으로 오른다 → 정답 공개. 3라운드 | 4개 중 선택, 정답 공개 후 "맞았어요!" |
| ④ 한 줄 소감 + 토론 | 2:00 | 소감이 **실시간 카드 벽**으로 올라온다(익명). 그 위에 토론 질문 3개 | "오늘 알게 된 것 한 줄" 입력 |

- ③ 퀴즈는 MIT 연구의 또 하나의 발견을 몸으로 겪게 한다: **AI 글은 서로 닮아 있고, 사람들은 그걸 알아본다.**
  반 전체가 AI 글을 높은 확률로 골라내면 "AI 글은 내 글이 아니다"가 느낌이 아니라 사실이 된다.
  (반대로 못 골라내면 그것도 토론 거리다.)
- ④ 토론 질문 (큰 화면 하단 고정)
  1. AI 글은 방금 읽었는데 왜 기억이 안 날까? 직접 쓴 글은 왜 기억날까?
  2. AI 초안을 많이 고친 친구들은 기억이 더 좋았을까? (**수정 비율 ↔ 기억 점수 산점도**를 띄운다)
  3. AI와 글을 쓰더라도 "내 글"로 남기려면 어떻게 써야 할까?
- **나눔 뒤에도 남는 것**: 교수자가 **[수업 리포트 링크]** 를 만들면 익명 집계·갤러리·소감 벽이 담긴
  읽기 전용 페이지가 생긴다. 학생 복습용, 동료 교사·학부모 공유용. 원문은 동의한 글만, 닉네임 없이.

### 7-4. 교수자 자신도 먼저 체험
"수업 만들기" 전에 **[나 먼저 10분 체험]** 버튼을 둔다. 교수자가 자기 청구서를 받아 본 뒤
수업을 만들어야 토론을 이끌 수 있다. 연수에서는 이 순서가 그대로 프로그램이 된다.

## 9. 기술 구상

**MVP = 솔로 모드, 프런트엔드만.**
- Vite + React + TypeScript, Tailwind. 모바일 우선, 정적 배포(Vercel).
- 상태·결과는 localStorage. 서버 없음.
- 콘텐츠 JSON: 주제 쌍, 주제별 찬성/반대 초안 각 3개, 도움말 문장, 설문 문항.
- 핵심 함수 3개
  - `similarity(a, b)`: 공백·문장부호 제거 → 글자 2-gram Dice → 0~100
  - `makeCloze(text)`: 첫 문장 제외, 어절 분리, 길이 ≥ 2, 비인접 긴 어절 3개 선택
  - `editRatio(draft, final)`: 편집 거리 / 초안 길이
- AI 도우미는 스크립트 응답 + 타이핑 애니메이션. 실제 모델 연결은 설정으로 분리.

**2단계 = 교수자 모드 (운영·수합·나눔).** 실시간이 필요해 백엔드가 들어간다. Supabase가 맞다
(Postgres + Realtime + Row Level Security, 서버 코드 거의 없음).

테이블 5개
```
sessions      (code PK, pin_hash, settings_json, stage, created_at, expires_at)
participants  (id, session_code, nickname, consent_share, stage, last_seen_at, joined_at)
results       (participant_id PK, payload_json, finished_at)        -- 아래 스키마 전체
votes         (id, session_code, participant_id, quiz_round, choice, created_at)
reflections   (id, session_code, participant_id, text, created_at)
```
- 학생 폰 ↔ 교수자 화면은 `participants.stage`, `votes`, `reflections` 를 Realtime 구독.
- 교수자 제어(모두 시작, 다음 단계, 반 결과 공개, 퀴즈 라운드)는 `sessions.stage` 한 컬럼을 바꾸는 것으로 끝.
  학생 앱은 이 컬럼을 구독해 화면을 바꾼다.
- 권한: 학생은 자기 participant/result 행만 쓰기, 자기 세션의 집계만 읽기. 교수자는 PIN으로 발급받은
  토큰으로 세션 전체 읽기·쓰기. 원문은 교수자와 본인만. 갤러리·퀴즈는 `consent_share = true` 행만.
- 수업 리포트(T4)는 세션 종료 시 **익명 집계 스냅샷 JSON**을 따로 만들어 읽기 전용 링크로 제공.
  원본이 삭제돼도 리포트는 남는다(원문은 동의 글만, 닉네임 제거).
- 보관: `expires_at` 기본 30일, 교수자가 연장·즉시 삭제. 만료 행은 일 1회 배치로 삭제.

**결과 스키마 (results.payload_json, 1인 1행)**
```
order(self_first|ai_first), topic_self, topic_ai,
self_text, self_time, self_chars, self_keystrokes,
ai_text, ai_draft, ai_prompt, ai_chip, ai_regen_count, ai_edit_ratio, ai_read_time, ai_time,
pred_self, pred_ai,
quote_self_text, quote_self_sim, quote_ai_text, quote_ai_sim,
cloze_self_answers, cloze_self, cloze_ai_answers, cloze_ai,
own_self, own_ai,
survey_ai_usage, event_log[]   -- (time, action) 타임라인
```

## 10. 주의할 점

- **시연이지 실험이 아니다.** n=1에서는 차이가 안 날 수 있다. 청구서 하단에
  "결과는 사람마다 다릅니다. 핵심은 '내가 어떻게 AI를 썼는가'를 돌아보는 것"을 넣는다.
- **타자 속도 격차.** 느린 학생은 직접 쓰기에서 2문장도 못 쓸 수 있다. 최소 기준을 낮게(2문장·40자),
  시간 끝나면 쓴 만큼 제출. 파일럿에서 직접 쓴 글의 인용 일치율 중앙값이 60% 이상 나오도록 분량을 조정한다.
- **차이가 너무 뻔하다는 반론.** "AI 글은 안 썼으니 당연히 기억 안 나지"가 나올 수 있다.
  그래서 (1) 학생이 직접 요청을 치고 고칠 수 있게 하고, (2) 시험 전 **예측**을 받아 두고,
  (3) 수정 비율과 기억의 관계를 보여 준다. 논점은 "AI가 나쁘다"가 아니라
  "읽기만 한 글은 내 머리에 남지 않는다"로 옮긴다.
- **MIT 연구 인용은 정확히.** 54명, EEG, 에세이, 2025년 프리프린트. "AI를 쓰면 멍청해진다"로 과장하지 않는다.
- **개인정보.** 닉네임만. 글 원문은 교수자와 본인만 보고, 수업 중 공개는 동의한 글만 익명으로. 보관은 기본 30일, 교수자가 연장·즉시 삭제.

## 11. 확장 모듈 (나중에)

- **규칙 찾기 퍼즐 모듈**(v1 구상): 숫자 기계·글자 규칙을 혼자 vs AI 튜터로 풀고 응용 문제로 학습 부채를 본다.
- **일주일 뒤 재시험 링크**: 같은 두 글에 대해 다시 인용 시험. 장기 기억 부채.
- **영어 글쓰기 버전**: 영어 교과용.
- **실제 LLM 모드**: 자유 주제, 실제 모델 초안. 소규모·고학년용.

## 12. 만들기 순서 제안

1. 콘텐츠 JSON(주제 3쌍, 초안 18개) + 유사도·빈칸 함수 + 솔로 모드 6화면(S0~S5). 여기까지가 "10분 체험".
2. 교수자 1명·학생 5명 파일럿. 글 분량, 타이머, 빈칸 난이도 조정.
3. Supabase + 운영(T0, T1) + 수합(T2). 동기 진행과 "반 결과 공개" 게이트까지. 이때부터 수업에서 쓸 수 있다.
4. 발표 모드(T3): 반 결과 애니메이션 → 갤러리 → 퀴즈 → 소감 벽. 학생 S6.
5. 수업 리포트(T4), 공유 카드 이미지, 재시험 링크, 확장 모듈.
